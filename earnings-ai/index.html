Ch. 01 How it started

A friend asked me if Apple's last quarter was actually good.

He'd read the headlines. He'd looked at the stock. He'd even opened the actual 10-Q that Apple had filed the week before. And he still couldn't tell me. Not because he was slow — because a 10-Q is 40 pages of legally-cautious prose written for the SEC, not for a person trying to decide if the company is doing well.

I opened one myself. Two paragraphs in I understood the problem. Every filing hides two or three sentences that actually matter — a shift in tone from management, a new risk factor, a change in guidance — buried inside pages of boilerplate that reads like a settlement agreement. The people who read these for a living are called analysts, and they charge for it.

Wait, so did they beat or miss? Just tell me if Apple is cooking. — My friend Sunny, on Apple's Q2 2026

I wanted to see how close a weekend could get me to what an analyst does — reading the filing, extracting the shifts, pairing it with the earnings-call transcript, checking the market's reaction — cheap enough that one ticker costs fractions of a cent, and fast enough that it feels like a Google search instead of a batch job.

Ch. 02 Identifying the problem

What actually matters in a 10-Q is usually two sentences long.

I pulled the last four quarters of AAPL 10-Qs and sat with them. Every filing had the same shape: table of contents, forward-looking-statements boilerplate, cash flow tables, a long risk-factors section, and — buried in there — three or four sentences that were actually new. Guidance moved. A supply-chain risk got upgraded. Management tone changed slightly.

A real snippet from Apple's Q3 2026 10-Q. The two highlighted lines are the ones a first-year analyst would flag. The rest is legal padding required by SEC form.

So the question was really a design question, not a modeling one.

Any decent LLM can read a 10-Q. The hard part is deciding what to show back. If you dump the model's raw answer, you get a wall of text. If you turn it into a dashboard of metric cards, you get every fintech tutorial's output. Neither of those is what my friend needed. He needed a page he could read in ninety seconds and then talk about at dinner.

Ch. 03 Version one, and why it wasn't enough

The first thing I shipped was a dashboard. That was the mistake.

I built the pipeline first — SEC EDGAR → HTML stripper → Groq → sentiment score — and delivered the output as the thing every fintech tutorial ships: four metric cards (Sentiment · Score · Filing Type · Filings Analyzed), a sentiment gauge, a Chart.js line chart of sentiment history, and cards for themes, quotes, risks, and guidance. It worked. It was also completely forgettable.

What made v1 forgettable wasn't the data — it was the format. A card grid is a UI for someone who already knows what they're looking for. My friend didn't. He wanted a page that told him what to think first, then let him drill in for evidence. The data I had was right; the framing was wrong.

Ch. 04 The redesign

Version two isn't a dashboard. It's a page from a magazine.

I threw the grid out and rebuilt the output as a single editorial page — a "Filing Brief" — that reads like a Bloomberg opinion column. Bicentra Biotech's brand identity was the reference for typography and restraint: precise cobalt on warm cream, generous vertical rhythm, three-column magazine layouts, italic serif callouts.

The brief has five moving parts. Each one earns its section number.

01
The Signal
A single paragraph telling you how sentiment moved across the last four quarters, with a sparkline embedded mid-sentence and a Manrope drop cap.

What Management Told You
A magazine-style pull quote from the CEO or CFO paired with the model's tone analysis and forward guidance. The quote is picked from the earnings call transcript when one exists; otherwise from the filing itself.

The five sections of a Filing Brief. Each one is a chapter, not a card.

The typographic system does most of the heavy lifting. Manrope 800 for the display voice. Cormorant Garamond italic for editorial labels, section eyebrows, and pull-figures. Inter for body prose. JetBrains Mono retired — it kept turning callouts into terminal output instead of magazine copy.

Ch. 05 Under the hood

Ticker in, filing brief out — and every step cached so re-runs are free.

The seven-step pipeline behind one submission:

// The pipeline behind one ticker submission: 1. ticker → SEC EDGAR // ticker → CIK → 4 recent filings 2. filings → HTML stripper // raw 10-Q text, cached by (cik, accession) 3. latest quarter → AlphaVantage // earnings call transcript, if available 4. filing + transcript → Groq LLM // gpt-oss-120b, cached by content_hash + prompt_version 5. older 3 filings → Groq LLM // quick sentiment scores → history sparkline 6. result → Turso (libsql) // runs table → permalink → shareable URL 7. filing date → yfinance // ±30-day price series, market reaction

Everything server-side. The frontend is a single HTML page that streams progress over Server-Sent Events, then renders the brief when the pipeline finishes.

Every step sits behind a Turso-backed cache keyed by content_hash + prompt_version, so a second run of the same ticker is instant and costs zero LLM tokens. Bump the prompt version → old rows age out naturally without a migration.

Ch. 06 Feature focus · Diff mode

Filings are only interesting relative to the last one.

So the app compares any two runs and tells you what actually changed. Four signals get surfaced by the diff engine:

  1. Sentiment shift. A signed delta between two runs' sentiment scores, plus the label flip if it crossed a threshold.
  2. Themes added and dropped. Set operations on the LLM's key-themes list — a new "AI acceleration" theme appearing three quarters in a row is a real signal.
  3. Beat / miss flip. When management stops missing estimates and starts beating them, the diff surfaces it explicitly instead of burying it in the summary.
  4. New analyst concerns. Only shows up when a transcript was available — pulls the questions analysts asked that last quarter's call didn't cover.

Ch. 07 Feature focus · Earnings call context

The 10-Q tells you the numbers. The call tells you the confidence.

When AlphaVantage has a transcript for the quarter, the analyzer feeds an excerpt of it into the LLM prompt alongside the filing itself. The model compares the polished written filing against how executives actually talked about it — and against what analysts pushed back on.

The brief gains an editorial pull quote from the CEO or CFO, a tone analysis grounded in the transcript, and a "What Analysts Pushed Back On" section rendered as a two-panel vs. layout. If no transcript is available, the section quietly disappears — the app degrades to filing-only mode with no error state and renumbers the remaining sections automatically.

Ch. 08 Decisions worth calling out

Six trade-offs that shaped the build.

Turso over Postgres

The app is read-heavy and SQLite-shaped. Turso keeps the SQLite dialect but runs the authoritative copy in the cloud with an embedded replica on the app machine — reads are local (nanoseconds), writes sync asynchronously. Free tier gives 9 GB storage and 1B reads/month, enough to never think about it. Postgres would have been a heavier dependency for zero gain.

Prompt versioning as invalidation

Instead of a TTL, the LLM cache is keyed by (content_hash, prompt_version, model). Any prompt change → bump the version constant → old rows are effectively invalid, new runs re-analyze. Old rows stay for provenance until pruned.

Server-Sent Events over polling

The analysis pipeline takes 8–25 seconds — long enough that a progress indicator matters. SSE gives me a single unidirectional stream of progress messages ending in the final result, and works with plain gunicorn --worker-class gthread. WebSockets would have been overkill.

API keys never leave the server

Groq and AlphaVantage keys live in Render secrets, injected as env vars. The frontend has no notion of them. A five-ticker demo whitelist caps blast radius from anyone hitting the URL — everything else is a friendly 403.

Editorial over dashboard

Every fintech tool defaults to a card grid. This one defaults to a single editorial page with progressive disclosure. The signal isn't a metric card labeled "Sentiment: +0.78" — it's a sentence: "Sentiment climbed from +0.20 in Feb 2026 to +0.78 today." Sparkline lives inside the sentence.

$0/month at 20 users

Render's free web tier + Turso's free storage tier. The container sleeps after 15 minutes of no traffic and wakes in ~1 minute on the next visit — disclosed to visitors directly via an "About this demo" pill so nothing feels broken. If cold starts ever matter, ~$0.20/month on Fly.io removes them.
