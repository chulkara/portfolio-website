The Signal

Sentiment climbed from +0.20 in Feb 2026 to +0.78 today, across 4 filings. Apple reported Q3 2026 net sales of $109.4 billion, up 16% year-over-year, driven by strong product and services growth.

The Problem

Every quarter, 10-Q filings arrive as 40+ pages of boilerplate that hide two or three sentences that actually matter.

Retail investors either skim, miss the shift in tone, or defer to headlines. Analysts pay Bloomberg terminals thousands a month for tools that pre-digest this. I wanted to see how close a weekend project could get.

The core question: could a language model surface the same signal a first-year analyst would pull out of a filing — beats, misses, guidance changes, new risk factors, tonal shifts — cheaply enough that a single ticker costs fractions of a cent, and quickly enough that it feels like a Google search rather than a batch job?

How it Works

Ticker in, filing brief out — with every step cached so re-runs are free.

The pipeline behind one submission. Two paths — a cached hit returns from Turso in milliseconds; a cold run fans through SEC EDGAR, an optional earnings-call transcript, and Groq's gpt-oss-120b before converging back to a rendered brief.

// The pipeline behind one ticker submission: 1. ticker → SEC EDGAR // ticker → CIK → 4 recent filings 2. filings → HTML stripper // raw 10-Q text, cached by (cik, accession) 3. latest quarter → AlphaVantage // earnings call transcript, if available 4. filing + transcript → Groq LLM // gpt-oss-120b, cached by content_hash + prompt_version 5. older 3 filings → yfinance // 30-day price reaction → history sparkline 6. result → Turso (libsql) // runs table → permalink → shareable URL 7. filing date → yfinance // ±30-day price series, market reaction

Everything server-side. The frontend is a single HTML page that streams progress over Server-Sent Events, then renders the brief when the pipeline finishes.

Every step sits behind a Turso-backed cache keyed by content_hash + prompt_version, so a second run of the same ticker is instant and costs zero LLM tokens. Bump the prompt version → old rows age out naturally without a migration.

The Redesign

The first version was a dashboard. That was the problem.

Version one landed the pipeline but delivered its output as a grid of metric cards, gauges, and Chart.js line charts. Functional, forgettable — the kind of thing every fintech tutorial ships. Nothing to forward to a friend.

Version two threw the dashboard out. In its place: a single editorial page — a "Filing Brief" — that reads like a Bloomberg opinion column with data woven through the prose. Section 01 is the signal, told as a paragraph with a sparkline embedded mid-sentence. Section 02 is the pull quote from management, magazine-style. Section 03 is analyst pushback from the earnings call, laid out as a "vs." panel. Section 04 is the market's answer, drawn as a Financial Times hairline chart with a small pill marker at the filing date. Everything else — themes, risks, insider trades, congressional trades — collapses under a single progressive-disclosure toggle labeled The Evidence.

The typographic system does the heavy lifting. Manrope 800 for the display voice, Cormorant Garamond italic for editorial labels and pull-figures, Inter for body prose. Bicentra Biotech's brand identity was the reference — precise cobalt on warm cream, generous vertical rhythm, restraint over decoration.

Feature Focus · Diff Mode

Filings are only interesting relative to the last one. So the app compares any two runs and tells you what actually changed.

  1. Sentiment shift. A signed delta between two runs' sentiment scores, plus the label flip if it crossed a threshold.
  2. Themes added and dropped. Set operations on the LLM's key-themes list — new "AI acceleration" theme appearing three quarters in a row is a real signal.
  3. Beat/miss flip. When management stops missing estimates and starts beating them, the diff surfaces it explicitly rather than burying it in the summary.
  4. New analyst concerns. Only shows up when a transcript was available — pulls the questions analysts asked that the previous quarter's call didn't cover.

Feature Focus · Earnings Call Context

The 10-Q tells you the numbers. The call tells you the confidence.

When AlphaVantage has a transcript for the quarter, the analyzer feeds an excerpt of it into the LLM prompt alongside the filing itself. The model gets to compare the polished written filing against how executives actually talked about it — and against what analysts pushed back on.

The output gains a management-tone field grounded in the transcript, key quotes prefixed with speaker names, and a new "analyst pushback" section. If no transcript is available, that section quietly disappears — the app degrades to filing-only mode with no error state.

Feature Focus · How sentiment is calculated

It's the LLM's read, not a formula.

The score isn't a lexicon count of positive and negative words, and it isn't calibrated against actual stock returns. It's a structured extraction: we hand Groq's gpt-oss-120b the raw filing (up to ~18k characters for the full pass), enforce JSON output, and ask it to return a sentiment label and a score at the same time. Both fields come back from a single call.

The full-analysis prompt looks roughly like this:

// Sent to Groq's gpt-oss-120b for the latest filing: You are a financial analyst. Analyze this SEC 10-Q for Apple Inc. (AAPL), filed 2026-07-31. FILING: <18,000 chars of stripped 10-Q text> // When a transcript is available, appended verbatim: EARNINGS CALL TRANSCRIPT (same quarter — use for management tone, analyst pushback, and forward-looking commentary): <8,000 chars of transcript excerpt> Return ONLY a valid JSON object: { "sentiment": "positive" | "neutral" | "negative", "sentiment_score": number from -1.0 to 1.0, "summary": "…", "key_themes": [ … ], "management_tone": "…", "key_quotes": [ … ], "guidance": [ … ], "risks": [ … ], "analyst_concerns": [ … ], "beats_estimates": true | false | null }

Two knobs matter. response_format is set to json_object — the model is forbidden from returning prose. And reasoning_effort is set to low — this is structured extraction, not a math proof; a chain of thought would burn tokens without improving the read.

Only the latest filing goes through the model. The three older filings on the history sparkline are scored from how the stock moved in the 30 trading days after each one (more on why below). Same −1 to 1 scale, zero extra LLM calls.

Every score is deterministic within a prompt version. The Turso cache key is (content_hash, prompt_version, model), so identical filing text always returns the same number. The moment I edit the prompt and bump the version constant (say v3 → v4), the cache misses and every ticker re-scores under the new prompt.

What the score is not.

  1. Not a lexicon count. No positive-words-minus-negative-words. VADER and FinBERT do that; this doesn't.
  2. Not calibrated against returns. A +0.78 doesn't mean the stock will go up 78%. It means the model read the writing as confidently positive.
  3. Not adjusted for company baseline. A chronically pessimistic filer might land at −0.2 in an objectively good quarter. What matters is the change.
  4. Not a substitute for the filing. If a number is going to move real money, you should still read the 10-Q. The brief exists to tell you which filings deserve that read.

That last point is why the Signal section leads with the sparkline of the last four quarters — not the current score in isolation. The trend shows how the market took each past filing, ending on how the model reads today's.

Feature Focus · The Three-Minute Timeout

The demo started timing out. The fix was to stop asking the AI questions the stock price already answers.

Every run was dying at exactly three minutes. The server logs showed why: each progress stream closed at 180 seconds on the dot, which is the app's own deadline. The pipeline was making four Groq calls in a row, one full analysis plus three quick scores for the history chart, and on a slow day for Groq's reasoning model that added up to more than three minutes.

The logs were also silent while it happened. Gunicorn buffers Python's output, so none of the progress messages showed up until it was too late to be useful. One environment variable, PYTHONUNBUFFERED=1, fixed that.

Let the market score the past.

The history chart exists to answer one question: how did each past filing land? The stock price already answers that, without an AI's opinion. So the three older filings are now scored from the price move in the 30 trading days after each one.

// Historical score, per older filing: move = close 30 trading days later ÷ close on filing day − 1 score = move ÷ 10%, capped to [−1, 1] // +10% or more reads as +1.0 label = positive above +0.2 · negative below −0.2 · otherwise neutral // Before → after, per run: Groq calls 4 → 1 stream deadline 180s → 300s // headroom for a slow Groq day

The newest point on the sparkline stays the model's read of the filing text. A filing that just came out doesn't have 30 trading days of price history yet, so the text is the only signal available for it.

Keeping it awake for $0.

The other kind of slow was the cold start. Render's free tier puts the app to sleep after 15 minutes without traffic, and waking it takes about a minute. That's a bad first impression if the person clicking is a recruiter.

  1. Fly.io. About $3–4 a month for one always-on machine, but there's no way to set a spending cap, so you have to watch the bill yourself.
  2. Hugging Face Spaces. Plenty of hardware, but running a Docker app there now requires a paid plan.
  3. Render's paid Starter plan. $7 a month for a fixed price and no cold starts. It's the right move once this becomes a product.
  4. What shipped: a free ping. cron-job.org hits the health-check endpoint every 10 minutes, so the app never goes 15 minutes without traffic. Render's 750 free hours a month cover one service running around the clock, since even a 31-day month is only 744 hours.

Feature Focus · The Information Gap

Filings are the polished story. Insider and congressional trades are what the informed money did about it.

Two datasets get pulled alongside every filing. Insider trades come from SEC Form 4 disclosures — every time a CEO, CFO, or 10% owner buys or sells their own company's stock, they have to file within two business days. Congressional trades come from the House Clerk's Financial Disclosures database — U.S. representatives disclose their personal trades within 45 days, per the STOCK Act of 2012.

Both feeds are lagging, both are self-reported, and both carry signal individually. The interesting question isn't whether either group traded — it's whether they agree. When the two disagree, the divergence is often the most useful piece of information in the whole brief.

The four states of the information gap. Agreement is a confirming signal. Divergence — especially executives selling into congressional buying — is what a Bloomberg terminal would highlight in red. The brief lays them side by side and lets you read the disagreement.

The two datasets never get merged into a single score — that would be false precision. They stay side-by-side in the Evidence section of the brief, sorted by date, so you can eyeball the pattern yourself: whose money is moving first, and does it match what the filing is telling you?

Decisions worth calling out

Turso over Postgres

The app is SQLite-shaped and read-heavy. Turso runs the authoritative copy in the cloud with an embedded replica on the machine, so reads are local and writes sync asynchronously. Postgres would have been a heavier dependency for zero gain.

Prompt versioning as invalidation

Instead of a TTL, the LLM cache is keyed by (content_hash, prompt_version, model). Bump the version constant and old rows are effectively invalid — new runs re-analyze automatically.

Server-Sent Events over polling

The pipeline takes 8–25 seconds, long enough that a progress indicator matters. SSE gives me a single stream of progress messages and works with plain gunicorn --worker-class gthread — WebSockets would have been overkill.

API keys never leave the server

Groq and AlphaVantage keys live in Render secrets — the frontend has no notion of them. A five-ticker demo whitelist caps blast radius; everything else gets a friendly 403.

Editorial over dashboard

Every fintech tool defaults to a card grid; this one defaults to a single editorial page. The signal isn't a card labeled "Sentiment: +0.78" — it's a sentence with the sparkline inside it.

$0/month at 20 users

Render's free web tier plus Turso's free storage. A free cron ping every 10 minutes keeps the container from sleeping, so there's no one-minute cold start on the first click.
